# Как помочь проекту

Спасибо, что заглянули! Проект держится на простоте: обычный JavaScript, никакой сборки и библиотек. Расширение запускается прямо из папки `src/`.

## Быстрый старт

```sh
git clone https://github.com/iArtem88/rutracker-games.git
cd rutracker-games
npm install        # только для тестов и сборки, в расширение ничего не попадает
npm test           # тесты разбора описаний, гоняются в настоящем Chromium
npm run test:e2e   # расширение целиком в Google Chrome на поддельном RuTracker (tests/e2e), около минуты
```

Чтобы запустить в браузере, откройте `chrome://extensions`, включите «Режим разработчика» и нажмите «Загрузить распакованное расширение», указав папку `src/`. После правок нажмите «Обновить» на карточке расширения и обновите страницу RuTracker.

Если тестам не хватает браузера, выполните `npx playwright install chromium` или поставьте Google Chrome.

Картинки: значки `src/icons/icon-*.png` собираются из логотипа `docs/media/logo.png` командой `npm run icons`, скриншоты настроек — `node tests/e2e/screenshots.mjs`.

## Как всё устроено

```
src/
  manifest.json          что и где запускается
  _locales/              название и описание для магазинов на 10 языках
  lib/i18n.js            языки, t('ключ') и названия меток для языков
  locales/*.js           тексты интерфейса: en.js — эталон, остальные — переводы
  lib/settings.js        настройки (общие для страницы и окна настроек)
  content/registry.js    список разделов: registerSection(), sectionForForum()
  content/games.js       общее для игр: скриншоты, русская озвучка/текст, их метки и фильтры
  sections/*.js          разделы: какие форумы и что в них особенного
  content/content.js     работа со страницей: строки, загрузка, кэш, метки, панель фильтров
  content/content.css    вид меток, скриншотов и панели
  ui/settings.*          окно расширения и страница настроек
  background.js          открывает настройки по кнопке на панели фильтров
tests/parse.test.mjs     разбор описаний на реальных формулировках раздач
scripts/build.mjs        zip-пакеты для Chrome и Firefox
```

Расширение открывает тему (`viewtopic.php`) и кэширует её первый пост (`.post_body`) на 30 дней, а разбирает его заново при каждом показе: новая версия разбора работает на старом кэше без новых запросов к сайту. Тема загружается снова, если в списке сменились её название или размер торрента (`releaseMark` в `content.js`). Делает оно это бережно: только для раздач, до которых дошёл пользователь, не больше 2 запросов сразу, с паузой 400 мс между ними и долгой паузой, когда сайт перегружен или ограничивает запросы (429, 5xx, 403 от Cloudflare).

## Добавить раздел

Раздел — это один файл в `src/sections/`. Самый простой пример — [`consoles.js`](src/sections/consoles.js), где есть только номера форумов. Этого уже хватает для скриншотов, меток языка и фильтров по ним.

1. Скопируйте [`docs/section-template.js`](docs/section-template.js) в `src/sections/<раздел>.js` и впишите номера форумов: это `f=` из адреса `viewforum.php?f=…`.
2. Добавьте файл в `manifest.json`, в список `content_scripts[0].js` перед `content/content.js`. Окно настроек подхватит его само.
3. Если у раздела есть своя полезная метка (как разгон у Switch или прошивка у PS), опишите её в `parse` и `badges`, её цвета — в `styles` (они сразу появятся на вкладке «Внешний вид»), а при желании добавьте фильтр в `filters` и настройку в `settings`. Примеры: [`switch.js`](src/sections/switch.js), [`playstation.js`](src/sections/playstation.js), [`windows.js`](src/sections/windows.js). Если метка ставится по словам, сделайте их настройкой `type: 'words'` со встроенным списком в `builtIn`: пользователи смогут дописать свои в блоке «Свои слова для меток» (так устроен `OC_WORDS` в `switch.js`), а `parse` получит их в `settings`.
4. Добавьте в `tests/parse.test.mjs` пару случаев с настоящими фразами из раздач этого раздела.

Если разделу нужны данные с другого сайта (как оценка Steam Deck в `windows.js`), запрос делает `background.js`. Сайт добавляется в `optional_host_permissions` манифеста и в `permissions` настройки, которая включает функцию: так браузер спросит пользователя, а без согласия запросов не будет.

Все тексты для пользователя берутся из словарей `src/locales/*.js` через `t('ключ')`. В описании раздела `title`, `label` и `options` задаются ключами. Новые ключи добавьте во все 10 файлов: тест «locales» проверит, что ни один язык не забыт.

Все файлы работают в одном общем пространстве имён, поэтому давайте своим константам и функциям имена с приставкой раздела (`PS_…`, `findRam`), чтобы не столкнуться с чужими.

## Правила

- **Просто и понятно.** Лучше одна полезная метка, чем пять «на всякий случай». Тексты для пользователя пишите по-русски и по-человечески, без жаргона.
- **Без зависимостей и удалённого кода.** Всё, что попадает в `src/`, лежит в репозитории.
- **Бережно к сайту.** Никаких новых запросов сверх страницы темы.
- **Разбор опирается на настоящие раздачи.** Приложите к PR ссылки на 2–3 темы, на которых проверяли.
- Перед PR выполните `npm test`, `npm run test:e2e` и `npm run lint:firefox`.

## Добавить язык интерфейса

1. Скопируйте `src/locales/en.js` в `src/locales/<код>.js` и переведите тексты. Подстановки в фигурных скобках (`{n}`, `{language}`) оставьте как есть.
2. Добавьте код в `LANGUAGES` и `NATIVE_NAMES` в `src/lib/i18n.js`, а файл — в `manifest.json` после остальных `locales/`.
3. Для магазинов добавьте `src/_locales/<код>/messages.json` (описание до 132 символов).
4. Чтобы метки озвучки и текста узнавали этот язык в раздачах, допишите его в `LANGUAGE_NAMES`, `LANGUAGE_STEMS`, `LANGUAGE_ENGLISH` и `TITLE_CODES` в `src/content/games.js`.

## Нашли ошибку в метке

Создайте issue со ссылкой на раздачу, указав, какая метка стоит и какая должна быть. Это лучший вклад: так разбор становится точнее для всех.
